# 阳光社区报修系统 - 系统设计文档

> **版本**: 1.0
> **日期**: 2026-01-11
> **项目**: 阳光社区报修系统 (Community Repair Reporting System)

## 1. 项目背景

### 1.1 需要解决的四个核心问题

| 问题 | 描述 | 原因分析 |
|------|------|----------|
| **渠道单一** | 电话+纸质模式造成沟通失真 | 移动化管理终端的应用缺位 |
| **过程黑盒** | 居民不知道维修进度，造成信任危机 | 串行人工传递模式的反馈滞后 |
| **数据孤岛** | 纸质单据无法关联分析 | 缺乏数字化存储与关联分析能力 |
| **缺乏考核** | 没有量化指标监控服务质量 | 数字化管理思维与考核逻辑滞后 |

### 1.2 技术架构

- **前端**: 微信小程序（MINA框架）
- **后端**: Python + Flask
- **数据库**: MySQL
- **架构模式**: 前后端分离，RESTful API

## 2. 用户角色

系统包含四种用户角色：

| 角色 | 主要职责 |
|------|----------|
| **居民** | 提交报修、查看进度、完成评价 |
| **维修人员** | 接收工单、更新进度、完成维修 |
| **物业管理员** | 审核工单、分配任务、管理类别、查看统计 |
| **超级管理员** | 管理用户账号、系统配置、数据维护 |

## 3. 核心功能模块

### 3.1 模块一：报修提交

**解决问题**: 渠道单一

| 功能 | 说明 |
|------|------|
| 拍照报修 | 居民可拍照/选择相册图片描述问题 |
| 位置选择 | 选择楼栋、单元、房号或公共区域 |
| 类别选择 | 从管理员配置的维修类别中选择 |
| 问题描述 | 文字描述具体问题 |
| 联系方式 | 自动填充或手动输入电话 |

### 3.2 模块二：进度追踪

**解决问题**: 过程黑盒

| 功能 | 说明 |
|------|------|
| 工单状态流转 | 待审核 → 已分配 → 处理中 → 已完成 → 已评价 |
| 实时进度推送 | 状态变更时通过小程序消息通知居民 |
| 进度时间线 | 居民可查看工单每个节点的时间和操作人 |
| 维修反馈 | 维修人员可上传维修过程照片和说明 |

### 3.3 模块三：工单管理

**使用角色**: 物业管理员

| 功能 | 说明 |
|------|------|
| 工单审核 | 审核居民提交的报修，确认有效性 |
| 手动分配 | 将工单指派给具体维修人员 |
| 工单列表 | 按状态、类别、时间筛选查看所有工单 |
| 类别管理 | 自定义添加/编辑/删除维修类别 |

### 3.4 模块四：数字档案

**解决问题**: 数据孤岛

| 功能 | 说明 |
|------|------|
| 历史工单查询 | 按位置、类别、时间等条件检索历史记录 |
| 工单详情存档 | 完整保存报修内容、处理过程、维修照片 |
| 数据导出 | 支持导出工单数据为 Excel |

### 3.5 模块五：统计报表

**解决问题**: 缺乏考核（服务质量监控）

| 功能 | 说明 |
|------|------|
| 工单统计 | 按时间段统计工单数量、各类别分布 |
| 处理效率 | 平均处理时长、各状态工单占比 |
| 居民评价汇总 | 评分分布、评价内容查看（仅作参考） |

### 3.6 模块六：用户管理

**使用角色**: 超级管理员

| 功能 | 说明 |
|------|------|
| 账号管理 | 创建/编辑/禁用各角色用户账号 |
| 角色分配 | 设置用户角色（居民/维修人员/管理员） |
| 小区配置 | 配置楼栋、单元等基础信息 |

### 3.7 模块七：居民评价

**解决问题**: 缺乏考核（服务质量监控）

| 功能 | 说明 |
|------|------|
| 评分 | 维修完成后居民打分（1-5星） |
| 评价内容 | 可填写文字评价（选填） |
| 查看评价 | 管理员可查看所有评价记录 |

## 4. 工单状态流转

```
[居民提交] → 待审核 → [管理员审核] → 已分配 → [维修人员接单]
    → 处理中 → [维修完成] → 已完成 → [居民评价] → 已评价
```

## 5. 功能与问题对照表

| 序号 | 模块名称 | 解决的核心问题 |
|------|----------|----------------|
| 1 | 报修提交 | 渠道单一 |
| 2 | 进度追踪 | 过程黑盒 |
| 3 | 工单管理 | 过程黑盒 |
| 4 | 数字档案 | 数据孤岛 |
| 5 | 统计报表 | 缺乏考核（质量监控） |
| 6 | 用户管理 | 系统基础设施 |
| 7 | 居民评价 | 缺乏考核（质量监控） |

## 6. 关键业务规则

1. **工单分配方式**: 物业管理员手动分配给维修人员
2. **维修类别**: 由物业管理员自定义配置，系统不预设
3. **居民评价**: 仅作为服务质量参考，不用于人员考核
